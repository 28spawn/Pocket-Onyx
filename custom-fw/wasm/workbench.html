What this is

The screen is the firmware's own pa_ui_render() and the sound is the firmware's own DSP — the Q21 NAM GRU with its 512-entry activation LUTs, the Q18 partitioned cabinet FIR, the 8-slot chain and the output limiter. Only the board layer is replaced: the panel becomes a canvas, the buttons become DOM elements, the SPI NOR becomes a 1 MB in-memory image, and the device's own allocator provides the real DSP SRAM budget (147,456 B - the same PA_DSP_POOL_BYTES the firmware uses).

A browser has no ASIO API, so this page uses the OS audio API. For a real ASIO device (Focusrite, Steinberg, ...) use the ASIO tab, which drives the Python emulator — the same firmware, the same DSP, real ASIO in and out.

ASIO I/O for the processed audio

Web Audio has no ASIO API — the browser can only use the OS device (WASAPI/CoreAudio/ALSA). A real ASIO interface is reached through the Python emulator, which already enables ASIO in PortAudio and streams a live input through the firmware's DSP and back out to the interface.

Using ASIO from the browser instead

If you would rather stay in the browser, install an ASIO4ALL bridge (or use the driver your interface ships) so Windows exposes the ASIO device as a WASAPI endpoint. The browser then sees it as an ordinary output device and this page's Output selector can pick it.

Note that browsers apply their own output latency and resampling, so for low-latency monitoring the Python emulator (direct ASIO) is the better path.

Flash image (1 MB NOR)

Holds the 80 presets (A/B banks), the system settings and the user NAM registry and capture of the real 1 MB chip — the layout in include/pa_flash_map.h.

NAM / IR import

A .nam or .wav is written into the flash image the way the device's SysEx cmd-25 upload path does it.

Preset store

The 80 slots of the device's own store (40 factory, 40 user). Change a user slot's name to write the record back, or store the sound that is playing right now into it. The record is the same 164 bytes the device keeps, so a slot written here can be pushed to a unit unchanged.

Bypassing the cabinet

  1. On the Home grid move the cursor onto the CAB tile with < / >.
  2. PARA click opens the Block Editor.
  3. Move the cursor to the far-left ON/OFF pill and press PARA click again — the cabinet leaves the signal path, click-free over one audio block, and the tile dims.
  4. PARA click again brings it back, with the cabinet you selected.

The state is saved with the preset. If the tile still shows the cabinet as on but you hear none, check Settings → Input/Output → CAB ON LINE OUT: in LINE output mode with that switch off the chain skips the cabinet, and the tile is marked NOCAB so it cannot be a mystery.

Limits this build reproduces

  • The 147,456 B DSP SRAM pool is the device's real allocator, and the real high-water mark (136,336 B with every effect on) is reachable from the UI.
  • The CPU load is a calibrated per-slot cycle model measured on the device, so it matches what the hardware reports.
  • The model is A2-Lite (3-channel) everywhere, so the browser cannot load a capture the device would refuse.
  • USB audio and BLE are inert in a browser; the rest of the chain is not.
